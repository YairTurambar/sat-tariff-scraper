## Design reference vs renderer baseline

These four PNGs are the **design reference**: the layout a human approved.
They are produced by Excel, are never regenerated by this project and must
never be replaced to make a test pass. They are compared tolerantly, because
the project renders with LibreOffice.

The **renderer baseline** lives in `tests/visual/baselines/libreoffice/` and is
produced by the project's own render pipeline from the approved workbook. It is
compared strictly (pixel equality in practice) and is regenerated only with
`python scripts/update_visual_baseline.py --confirm`.

## Latest offline comparison (design mode)

Using `scripts/sample_workbook.py`, LibreOffice 24.2.7.2, `pdftoppm 24.02.0`,
Pillow, NumPy and scikit-image, rendering at 200 dpi:

| Sheet | Mean abs diff | SSIM | Reference | Rendered page | Normalized canvas |
| --- | ---: | ---: | --- | --- | --- |
| Derechos e impuestos | 0.1124 | 0.4912 | 1853×91 | 2200×1700 | 1901×104 |
| Nomenclatura | 0.0973 | 0.5391 | 1531×124 | 2200×1700 | 1921×217 |
| Restricciones | 0.1179 | 0.4775 | 1492×147 | 2200×1700 | 1916×208 |
| Cuotas | 0.1295 | 0.5341 | 1460×137 | 2200×1700 | 1912×351 |

Previous values, for comparison (crop-to-shortest normalization, 150 dpi):
0.2017/0.0762, 0.1540/0.2190, 0.1805/0.1303 and 0.2593/0.0818. The design
thresholds are mean ≤ 0.18 and SSIM ≥ 0.35; they were raised from the previous
SSIM 0.07 **because the measured values improved**, not to accommodate a
failure.

### Why the remaining difference exists

- LibreOffice and Excel rasterize text with different fonts, hinting and
  anti-aliasing.
- Excel auto-sizes row heights from its own font metrics. The exporter now
  pins an explicit data-row height (`DATA_LINE_HEIGHT`) so both engines agree,
  but the captures themselves use slightly different heights per sheet
  (≈15 pt in Nomenclatura, ≈19 pt in Derechos, ≈26 pt in Cuotas/Restricciones).
- The `Código` column of `Derechos e impuestos` shows `DAI | IVA` (the exporter
  joins every duty code present in the row) while the capture shows a single
  code per row. This is a **content** difference, deliberately not "fixed" by
  changing the capture; it is covered by the structural assertions instead.

No pixel-equivalence claim is made for these four comparisons.

## Running the comparison

1. Re-read the screenshots against `docs/excel-format-specification.md` and
   correct any discrepancy (headers, merges, colors, borders, alignment,
   sizes, filters, and freeze panes).
2. Run the reproducible render/compare pipeline:

   ```bash
   pip install -e ".[visual]"
   python scripts/compare_excel_visual.py --mode design
   python scripts/compare_excel_visual.py --mode baseline
   ```

   This exports a deterministic fixture workbook, renders each sheet to PNG
   with LibreOffice + poppler, and prints a mean-pixel-difference/SSIM table
   per sheet, writing diff images under `artifacts/visual/` (git-ignored).
3. Run `python -m pytest tests/visual -v`. It executes when LibreOffice,
   poppler, and the visual Python dependencies are installed.
4. Record per-sheet mean absolute pixel difference, SSIM, source dimensions,
   normalized dimensions, and remaining differences. These are tolerant
   cross-renderer metrics, not pixel-perfect equivalence.
